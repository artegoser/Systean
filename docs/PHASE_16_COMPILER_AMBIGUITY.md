# Phase 16 — Whole-language compiler and ambiguity suite

Phase 16 turns Systean's unambiguity requirement into a package-compilation invariant. A versioned language directory is no longer accepted merely because each module parses independently: `LanguagePackage::load` routes through `WholeLanguageCompiler`, compiles the complete normative package, and rejects cross-layer conflicts before returning an immutable `LanguagePackage`.

## Package manifest and provenance

`language/package.toml` is the package-level source of truth for:

- language package name, semantic version, and revision;
- provenance pointers;
- the expected version of every normative TOML module;
- compatibility epoch;
- frozen compatibility/adversarial corpus locations;
- the bounded exhaustive ambiguity depth.

Compilation checks every declared module version against its own `meta.version`. Provenance is collected from the normative `.toml`, `.semsys`, and `.tsv` sources (excluding `legacy/`) in deterministic path order. Each source receives a stable digest and the package receives a deterministic aggregate fingerprint. The fingerprint is provenance, not a cryptographic signature.

In-memory `from_sources*` constructors intentionally use a synthetic revision-zero manifest. They continue to support partial test/embedding fixtures and do not pretend to be a versioned whole-language package.

## Compilation pipeline

For a versioned package, compilation performs the existing per-layer validation first and then the Phase 16 whole-package passes:

1. verify manifest/module version agreement;
2. build one ownership table for lexical roots, structural markers, text boundaries, readability punctuation, structured-literal reserved forms, unit spoken forms, and unit written symbols;
3. reject collisions in overlapping spoken/written channels;
4. compare spoken owners by canonical phonological pronunciation;
5. generate a deterministic AST corpus spanning lexical categories, predicates, operators, quantifiers, references, information forms, quotations, and representative structured-literal families;
6. require every generated AST to linearize and parse back identically;
7. reject any canonical surface generated by distinct ASTs, independently of recursive-descent parser branch order;
8. compare complete generated spoken streams by pronunciation;
9. lower generatable ASTs semantically and require the reparsed canonical form to lower to the same canonical semantic term;
10. exhaustively enumerate short expressions from one representative token per grammar family up to the manifest bound, and reparse every accepted canonical result;
11. compile the frozen compatibility and adversarial corpora as normative package inputs.

The resulting counters are stored in `PackageValidationReport` and the provenance is available through `LanguagePackage::provenance()` and `LanguagePackage::package_fingerprint()`.

## Frozen corpora

`language/corpus/compatibility.tsv` freezes representative source → canonical surface → type → canonical semantics tuples. Any compatible revision in the same compatibility epoch must keep those observations stable. `LanguagePackage::compatibility_snapshot` and `diff_compatibility` provide the revision-to-revision comparison API; an epoch change is explicitly incompatible rather than silently accepted.

`language/corpus/adversarial.tsv` freezes inputs that must either be rejected or canonicalize to exactly one declared surface. This covers malformed/noncanonical inputs as well as scope/associativity normalization cases where parser implementation order must not become observable semantics.

## Failure model

Normative conflicts are compile failures, reported as `LanguageError::Package` with structured `PackageInvariantError` values. Relevant failures include:

- module/manifest version mismatch;
- cross-layer surface ownership collision;
- spoken pronunciation collision;
- multiple AST owners for one generated canonical surface;
- AST or semantic round-trip drift;
- frozen corpus drift.

This keeps ambiguity handling out of parser precedence accidents: a versioned package that violates a central invariant does not load.

## Validation

The dedicated regression suite is `crates/systean-core/tests/compiler_phase16.rs`. Run the normal repository validation on the author toolchain:

```bash
cargo test --workspace
```

Phase 17 can expose the already-compiled manifest, provenance, validation report, and package fingerprint through CLI/WASM/API surfaces without moving package validation out of the core.
