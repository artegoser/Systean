# Phase 20 — English reference documentation and controlled rendering

Status: **implementation complete; Rust toolchain validation pending**
Depends on: Phases 18–19

## Goal

Make the complete public Systean vocabulary learnable and explainable in English, and provide one deterministic English rendering path for Systean expressions without making English part of normative Systean semantics.

English is the fixed bridge language for Systean 1.0. Other natural-language documentation/renderers are explicitly deferred until they can be designed as independent consumers of canonical semantics rather than as naive substitutions over English.

## Per-word documentation contract

Every public word must have a compiled English documentation entry.

Required fields:

- [x] `gloss`: short English equivalent suitable for search results and hover UI;
- [x] `explain`: precise English explanation of the semantic contribution;
- [x] canonical semantic signature, included by reference from the compiled declaration rather than duplicated as prose data;
- [x] pronunciation/stress, included from the phonology engine rather than duplicated;
- [x] at least one canonical Systean example;
- [x] controlled English rendering for the example generated by the renderer, not manually allowed to drift silently.

Where applicable, the explanation must state:

- [x] argument roles in human terms;
- [x] what the word does **not** imply when that distinction matters;
- [x] scope behavior;
- [x] discourse/reference/context effect;
- [x] whether the declaration is primitive, defined, or intrinsic-backed;
- [x] relevant contrast words that users are likely to confuse.

Operators/constructions require at least one example that makes their scope/attachment behavior visible.

## Documentation source format

Human documentation is stored separately from normative semantic declarations, tentatively under:

```text
language/docs/en.sydoc
```

Representative shape:

```text
word vid {
    gloss "see";
    explain """
    Expresses visual perception by the first participant of the second participant.
    It does not itself assert recognition, belief, attention, or duration.
    """;

    example "sol vid sol";
    expect_semantics """
    vid(observed = sol, observer = sol)
    """;
}
```

The documentation compiler resolves `vid` to the compiled symbol and rejects unknown or duplicate entries.
`expect_semantics` is committed teaching-material state, not generated documentation prose: package compilation rejects the example if the real parser/resolver produces a different canonical semantic term.

The source format must support splitting documentation into multiple files/modules once the vocabulary grows, without changing symbol identity.

## Coverage compiler

- [x] Package compilation exposes the set of public documented words/constructions.
- [x] A release check fails if a public 1.0 word lacks English `gloss` or `explain`.
- [x] Examples are parsed through the real Systean engine.
- [x] Example canonical semantics are stored/checked so a grammar change cannot silently change the teaching material.
- [x] Documentation has an independent fingerprint.
- [x] Documentation-only edits do not change semantic/surface fingerprints.

## Controlled English renderer

The renderer consumes canonical typed semantic structures, plus explicit discourse information where required, and produces deterministic English.

It is **not** word-for-word substitution.

Required properties:

- [x] compositional rendering for ordinary predicates/relations;
- [x] explicit rendering for logical negation/conjunction/disjunction;
- [x] quantifier rendering preserving scope;
- [x] controlled rendering for counted/generic/statistical claims;
- [x] explicit rendering for information status (`unknown`, `unspecified`, `withheld`) without inventing missing content;
- [x] context/reference rendering that uses resolved referents when a stable human label exists and otherwise remains explicit;
- [x] date/time/quantity/unit rendering from typed values;
- [x] speech-act/repair rendering that distinguishes propositional content from communicative/discourse effect;
- [x] deterministic parenthesization or explanatory phrasing where ordinary English would otherwise hide Systean scope;
- [x] no LLM/paraphraser in normative renderer tests.

## Controlled English vs idiomatic English

The site/API must label the deterministic output simply as `English` or `English rendering`, with documentation explaining that fidelity is prioritized over stylistic naturalness.

A future optional `natural paraphrase` feature may exist, but:

- it is non-normative;
- it cannot replace controlled English in tests;
- it cannot be used to decide Systean parse/meaning;
- it must be visually separated from deterministic rendering.

## Search/index data

The documentation compiler produces a user-facing search index containing at least:

- root;
- English gloss;
- English explanation text;
- semantic declaration kind;
- semantic result type;
- argument count/types;
- semantic/domain tags if manually declared as documentation metadata;
- examples;
- source/documentation provenance.

Search metadata must not be treated as semantic identity.

## Required validation

- [x] 100% of public 1.0 roots have English glosses and explanations.
- [x] All documentation examples parse and round-trip.
- [x] Controlled English rendering has golden tests across every major semantic subsystem.
- [x] Rendering never changes canonical Systean semantic terms.
- [x] English documentation edits alone change only the documentation fingerprint.
- [x] The renderer has explicit tests for ambiguous-looking English cases where Systean scope must remain visible.

## Completion result

Every public Systean word is teachable in English, every analyzed expression can receive a deterministic English interpretation, and no English wording participates in normative semantic identity.

## Implementation result

- `language/docs/en.sydoc` covers all 175 public typed word declarations with a gloss, explanation, metadata tags and at least one canonical executable example.
- The documentation compiler derives signatures and pronunciation from the compiled language package, rejects missing/unknown/duplicate entries, checks every example against its committed `expect_semantics` value and a canonical-semantic round-trip, generates example English, and owns a separate documentation fingerprint.
- `EnglishRenderer` renders canonical semantic terms deterministically with semantic-path alignments, explicit scope, information status, typed structured values and compiled surface/binder metadata.
- Native workbench, CLI and WASM APIs expose the documentation fingerprint, compiled word documentation, search-index data and deterministic English rendering. The site labels this output `English rendering` and keeps the broader learning/search UX in Phase 21.
- The Phase 20 validation suite covers documentation completeness and fingerprint isolation, major renderer subsystems, context resolution, structured quantities, semantic immutability and scope-sensitive English goldens.
